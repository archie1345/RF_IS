# RF_IS complete functional test matrix

This is the working inventory for functional and responsive verification. It was built from the current route list, five route files, policies/requests/controllers/actions, migrations and seeders, 46 Vue files under `resources/js/pages`, shared feature components, and the existing Pest and Playwright suites. The Vue count includes nested components and is not a count of unique Inertia routes.

There are 183 application routes after excluding Debugbar and Boost developer endpoints. Several are compatibility redirects or framework endpoints; they are listed below in the relevant workflow instead of being counted as separate business features. The application currently has three roles (`admin`, `coach`, `athlete`) and seven seeded combinations. The role fixture shared by desktop and mobile Playwright suites is `e2e/tests/role-coverage.ts`.

## Status and coverage rules

- `DISCOVERED`: behavior and test evidence are inventoried, but no complete browser workflow has passed.
- `PARTIAL`: one or more meaningful browser paths passed, but a listed action, error path, role, or viewport remains open.
- `TESTED`: Playwright exercised the UI action and asserted its resulting behavior. A page load alone does not qualify.
- `FIXED`: a reproduced defect was corrected and the regression path passed.
- `FAILED`: the most recent functional attempt failed and is not yet repaired.
- `BLOCKED`: the feature could not be exercised safely or the environment lacks the required capability.
- `NOT APPLICABLE`: the inspected application does not implement the feature.

For completion percentage, count a row only when its relevant positive path, negative or authorization path, data result, and listed viewport requirement have passed. Shared backend tests are recorded separately and do not turn a browser row into `TESTED`.
